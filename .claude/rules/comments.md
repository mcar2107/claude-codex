# Комментарии

1. JSDoc на русском. Предпочитай JSDoc вместо `//`; блок — многострочный (`jsdoc/multiline-blocks`). *(см. ниже)*
2. Комментарий осмысленный — не повторяет код, объясняет «почему», а не «что». *(см. ниже)*
3. Не скупись на пустые строки между абзацами длинного комментария.
4. Не описывай внутренности принимающей стороны — только observable behavior. *(см. ниже)*
5. Комментарий объясняет, почему код устроен так **сейчас**. История правок — в git. *(см. ниже)*
6. Закомментированный код — не комментарий. Удаляй: он есть в git.
7. Пустой `catch` — только с комментарием внутри, почему ошибку можно проглотить (`no-empty`).

## Подробности

### #1. JSDoc на русском

**Why:** конвенция проекта. JSDoc структурно привязан к функции, виден в IDE при вызове и переживает рефактор лучше
плавающего `//`.

**Хорошо:**

```js
/**
 * Обработчик отказа вешается до listen и колбэков: иначе они успеют отклонить промис без
 * обработчика.
 */
```

**Плохо:**

```js
/** Текст комментария */
// Текст комментария
```

---

### #2. Почему, а не что

**Why:** «что» уже написано в коде. Ценность комментария — контекст, которого из кода не видно: зачем так, какие
альтернативы отвалились, какой кейс ловим.

**Хорошо:**

```js
/**
 * Смерть родителя закрывает pipe — даже после SIGKILL.
 */
process.stdin.once('end', stop);
```

**Плохо** (повторяет код):

```js
// подписываемся на end у stdin
process.stdin.once('end', stop);
```

---

### #4. Только observable behavior

**Why:** пересказ внутренностей вызываемого модуля — хрупкая зависимость через текст. Особенно для vendor/ccr: его
обновят, и комментарий начнёт молча врать. Вызывающей стороне важно другое: что вернётся и что будет в краевых случаях.

Ссылки на **наши** файлы (`scripts/build.cjs`, `src/transport/shared.ts`) и на публичные точки upstream, которые
подменяет адаптер (`@/transformer`, `@caeliq/ccr-shared`), допустимы.

---

### #5. Про «сейчас», а не про историю

**Why:** «раньше было иначе» устаревает в момент написания и ничего не даёт читателю: перед ним текущий код, а не
предыдущая ревизия. История живёт в git.

**Запрещено:** «раньше здесь было», «переделали с X на Y», «прежнее поведение сохранено», «вернули как было».

**Можно:** сослагательное про **альтернативу**, если оно объясняет текущее решение:

```js
/**
 * Точный подсчёт важнее: работа в главном потоке лучше молчаливой оценки.
 */
```
