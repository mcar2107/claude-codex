# Стиль кода

Форматирование (prettier) и синтаксис (eslint) проверяют конфиги — здесь то, что они не ловят или ловят не целиком.

1. Только именованные экспорты: `export const`, не `export default`. Исключения — `src/transport/registry.ts` (его
   default-импортирует код vendor/ccr: `import Transformers from '@/transformer'`) и конфиги инструментов
   (`eslint.config.ts`, `lint-staged.config.ts`), которые читают default-экспорт.
2. Предпочитай ES-методы (`find`, `flatMap`, `Object.entries`). lodash в проекте нет — не тащи его ради одной утилиты.
3. Явный `return`, если функция возвращает значение (`arrow-body-style: always` в eslint).
4. `switch` предпочтительнее цепочки `if` по значениям одного union. *(см. ниже)*
5. `||` — дефолт по умолчанию; `??` — только с комментарием, почему falsy-значение надо сохранить. *(см. ниже)*
6. Выноси в константу, если значение повторяется или его семантика неочевидна. Тривиальные литералы (0, 1, '',
   уникальные для одного места) можно оставлять инлайном.
7. `async/await` вместо `.then()`; на верхнем уровне скрипта — top-level `await`.
8. Деструктуризация при любой возможности.
9. Условия Йоды (`'x' === getType()`) запрещены.
10. Присваивание внутри условия запрещено.
11. В новом коде — стрелочные функции; function declaration — только для перегрузок. Существующие декларации ради
    правила не переписываем: только вместе с правкой самой функции.
12. Комментарии и JSDoc — на русском (`comments.md`). Строки CLI (вывод, ошибки, `--help`) — на английском.
13. Экономь проходы по коллекции — цепочки `.filter().map()` (и обратные) сворачивай в один `.reduce`. *(см. ниже)*
14. Ленивый `await import()` внутри команды — норма: модуль грузится, только когда команде он нужен (`src/cli.ts`).

## Подробности

### #4. `switch` предпочтительнее `if`

**Why:** при переборе union/enum `switch` с `default: throw` сразу показывает необработанное значение; цепочка `if`
молча пропускает новый вариант.

**Когда применять:** перебор значений одного union / набора строк из ≥2 вариантов (команды CLI, уровни effort).
Бинарную проверку (`if (cond) return a; return b;`) оставлять `if`.

**Хорошо:**

```js
switch (command) {
  case 'login': {
    return login();
  }

  case 'status': {
    return status();
  }

  default: {
    throw new Error('Usage: claude-codex auth login|status');
  }
}
```

### #5. `||` как дефолт (falsy-коэрсия)

**Why:** пустая строка, `0` и `false` из env, JSON и ответов API обычно значат «значения нет». `??` оставит `''` или
`0` — это другое поведение и обычно баг.

**Хорошо:**

```js
const model = process.env.CLAUDE_CODEX_MODEL || DEFAULT_MODEL;
```

**Когда уместен `??`:** только если `0`, `''` или `false` — валидное значение. Комментарий обязателен:

```js
/**
 * Код выхода 0 — успех, а не «нет значения»: `||` превратил бы его в 1.
 */
process.exitCode = result.status ?? 1;
```

### #13. Экономь проходы по коллекции

**Why:** `.filter(...).map(...)` — два прохода и промежуточный массив, который сразу выбрасывается. Один `.reduce`
делает оба шага за проход.

**Enforce:** правило ast-grep `no-iterator-chain` (`filter` / `map` / `flatMap` подряд).

**Когда оставлять как есть:** одиночный вызов — просто `.filter`, просто `.map`, просто `.find`.

**Хорошо:**

```js
const answer = (result.content || []).reduce((text, item) => {
  return item.type === 'text' ? text + (item.text || '') : text;
}, '');
```

**Плохо** (два прохода + промежуточный массив):

```js
const answer = (result.content || [])
  .filter((item) => {
    return item.type === 'text';
  })
  .map((item) => {
    return item.text;
  })
  .join('');
```
